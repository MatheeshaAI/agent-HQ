# Agent HQ multi-provider setup and change record

**Status:** Provider support is implemented in the recovered source and built as a separate Windows app. The existing `Agent HQ.exe` at the workspace root was left unchanged.

## Changes made

- Added provider IDs and shared model-listing types to `agent-hq-source/src/shared/types.ts`.
- Replaced the single-provider engine construction with a provider adapter registry in `agent-hq-source/src/main/engine/llm/providers.ts`. The engine continues to call one structured-output interface.
- Kept the Anthropic API adapter and added OpenAI and OpenRouter Chat Completions adapters. Both request model lists from their provider endpoints and route structured requests through the shared schema parser.
- Added Claude Code CLI routing. It uses the locally installed `claude` command and its existing supported account login; model aliases can be listed in Settings.
- Added a generic ACP stdio adapter for Codex, OpenCode, Antigravity CLI, Kilo Code, and custom ACP agents. It performs ACP initialization, creates sessions, selects advertised models where supported, and routes completions. ACP model options are read from the agent's session configuration.
- Added per-provider API credential storage in `agent-hq-source/src/main/engine/settings.ts`, using Electron `safeStorage` where available and preserving migration from the old Anthropic `apiKey` setting.
- Added model listing and provider settings IPC through `agent-hq-source/src/main/engine/ipc.ts`, `agent-hq-source/src/preload/index.ts`, and the shared API contract.
- Reworked the settings view in `agent-hq-source/src/renderer/src/ui/views/SettingsView.tsx` with provider selection, API-key fields, CLI/ACP command and argument fields, model ID entry, model loading, and Claude Code login instructions.
- Recovered the missing application source files and 3D assets needed for a production build. `npm install` generated a lockfile in the recovered source project.
- Built the renderer/main bundles and packaged a separate Windows app at `agent-hq-source/dist/win-unpacked/Agent HQ.exe`.

## Provider setup

- **Anthropic API:** enter an Anthropic API key, then use **Load models** to populate model IDs.
- **Claude subscription:** select **Claude subscription (Claude Code)** and click **Sign in to Claude** to open a PowerShell terminal running `claude`; finish the Claude account login there. Then choose a model alias or enter a model ID. Agent HQ calls the official Claude Code CLI in print mode. Anthropic documents Claude account sign-in and the CLI print/output flags in its [Claude Code setup guide](https://docs.anthropic.com/en/docs/claude-code/getting-started) and [CLI reference](https://docs.anthropic.com/en/docs/claude-code/cli-usage).
- **OpenAI API / OpenRouter:** enter the provider API key, optionally set an OpenAI-compatible base URL, load models, and select a model ID.
- **Codex:** the provider preset uses `npx` with `@agentclientprotocol/codex-acp`. The Codex adapter must be installed/available through npm, and Codex account authentication must be completed in the supported CLI flow.
- **OpenCode:** the preset uses `opencode acp`; complete OpenCode's own provider login first. OpenCode documents that command in its [ACP support guide](https://docs.opencode.ai/docs/acp/).
- **Antigravity CLI, Kilo Code, and custom ACP:** provide an executable and arguments for an ACP-compatible agent. The CLI must actually expose ACP over stdio or have a compatible ACP bridge; a provider label alone cannot add ACP support to a CLI that does not speak the protocol. If an agent reports model options, **Load models** displays them; otherwise enter a model ID manually.

Image blocks are forwarded by the OpenAI-compatible and ACP adapters. PDF document blocks are currently accepted only by the Anthropic API adapter; other routes return a clear unsupported-content error rather than silently dropping the PDF. Claude Code CLI routing currently accepts text content only.

## Use the new build

Open `agent-hq-source/dist/win-unpacked/Agent HQ.exe`. This is a portable unpacked build; it does not replace the existing installation. Open **Settings → AI provider**, configure the provider and model, and save. For CLI providers, authenticate using that CLI's own login flow first.
